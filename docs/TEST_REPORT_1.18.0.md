## Delivered scope

Assigned staff can explicitly open one exact message from recent INBOX headers. Current actor, global mail.read permission, mailbox read assignment and saved account revision are mandatory, including owners. The existing pinned public destination/original-host verified TLS reader performs exact UIDVALIDITY/UID and size preflight checks, then BODY.PEEK with unchanged server read flags. Raw MIME is limited to 256 KiB including encoded attachments; decoded text, HTML, MIME complexity and sanitizer DOM work have separate limits. The released header limits stay unchanged.

Maintained ImapEngine 1.25.6, MIME parser 4.0.6 and Symfony HTML Sanitizer 7.4.20 are bundled with every pinned dependency/license byte (40 packages total); no customer Composer is required. Every transport result is raw MIME and is decoded through private parser state. Plaintext is escaped. Minimal formatting is isolated in an opaque sandbox iframe with restrictive CSP and no-referrer. Provider resources/scripts/forms/styles are excluded; external links require a user selection and open without referrer/opener. Missing DOM preserves plaintext with an unavailable-format explanation. A complete malformed MIME missing its closing boundary can be tolerated by the maintained parser; truncated network responses never qualify as success.

Separate additive tables retain exact identity, revision, actor, timestamps and outcome/size metadata. No raw MIME, sender, subject, body or password is retained in request history. Strict started and terminal audits commit separately; failure to record a result exposes no message. DNS runs outside the staff lock; current-authorized credential use is serialized with edits without holding an InnoDB transaction. Limits allow one request per account per two seconds and 240 per account and staff hour. GET navigation performs no mailbox connection or cached-content read.

## Owner procedure and remaining gates

Choose FULL-PROJECT for sanitized development source, COMPLETE-UPLOAD for fresh installation, or UPDATE for installed 1.0.8 or 1.1.0 through 1.17.0. Back up website, database, private mail-master.key and storage together. UPDATE creates cwp-update-1.18.0; use its authenticated owner procedure. Follow START-HERE and MIGRATION-INSTRUCTIONS. File recovery preserves additive database records and is not a database downgrade.

On upgrades, an owner opens Email accounts and selects Prepare message reading with their current password. Fresh installs create empty storage. Assign global mail.read and account Read access (including owners), then use My email accounts → Open inbox → Load recent headers → Open message. Older versions may first need inbox preparation. Whole messages over 256 KiB, including encoded attachments, must use a regular mail app.

Incoming transport supports 993/TLS and 143/mandatory STARTTLS with AUTH=PLAIN, a 20-second post-DNS deadline, five-second I/O/connect limits and 393,216 total received bytes. Real account compatibility, host DNS/egress/system trust and deployment remain separate acceptance. Attachments/downloads, sending, OAuth, other folders, synchronization and exact-message bells remain incomplete. No real mailbox, deployment, payment/provider write or SSH session occurred.
