Clients receive an in-portal activity center for existing studio messages, published design/proposal reviews, private files, invoices, recorded payments/corrections and published website ZIP releases. Staff with client-workspace access have a separate center for client replies, file uploads and review decisions. A bell links to the center, with links from each entry to the exact currently authorized source. Staff also see their workspace bell on public pages after a private authorization check; anonymous visitors and ordinary clients never receive staff data.

Use the existing durable source records as the event history, with stable typed keys and a separate per-person read-state table. No copied message bodies or business-write hooks: failure to read/update activity cannot roll back or duplicate an invoice, receipt, message or release. A later refresh re-reads the retained source. Reads happen only through explicit CSRF-protected POST actions; opening a bell, list or source does not mark everything read. Mark-visible applies only to the reviewed page's bounded authorized keys. Counts and read state are independent for every staff/client identity. Existing retained events initially appear unread after enablement. Missing/revoked sources disappear safely without opening an unrelated item.

All list/count/action/navigation paths recheck active identity and current client/project ownership. Staff grant revocation invalidates access immediately. Support cannot read or change a client's activity/read state. Admin and client contexts are explicit when a browser has both identities. Private JSON is no-store and same-origin, has no permissive CORS, returns no private payload when unavailable/unauthorized, and public HTML contains only a generic empty placeholder. Poll at most once per minute in an active visible page, with throttled focus refresh and no push/daemon claim. Unavailable/stale checks must not show a fabricated zero. Paginate history and cap the displayed unread count at 99+.

No SMTP/email outbox, delivery claim, preferences, project-stage timeline, hosting monitoring, renewal alerts, support-ticket events or admin-mail subjects/counts are included. These remain P-05/P-07/A-06–A-08 work. Source retention governs this activity history; no automatic deletion is introduced. No actual customer mail, payment, provider operation or live deployment.

## Setup and use

Published/download-verified in [v1.10.0](https://github.com/afterburn25/Cajun_Web/releases/tag/v1.10.0) at `4649a913d40166b9874f9550e57b4186edfc43ab` through PR #26; 603 native / 630 HTTP/Chromium checks pass. [Report](TEST_REPORT_1.10.0.md).

Existing sites back up the website, database and private storage, merge the flat UPDATE archive, then open **Workspace activity** as an owner and confirm the current password. Older sites first enable the client workspace and administrator accounts. Fresh one-page installation includes enabled empty read state. No daemon, SMTP account, hosting CLI or additional provider is required. Retained historical updates initially appear unread.

Clients open **Workspace activity** from the portal. Staff with client-workspace access open it from the administration sidebar. Bells show up to **99+** unread items and link to the appropriate center; each update links to the exact source. On the public website only signed-in authorized staff receive the workspace bell. A client and administrator may coexist in one browser; each page requests its explicit audience. Support sessions cannot access client activity. A revoked identity/grant removes the count and access at the next check; all navigations/actions independently validate current access.

Choose **All updates** or **Unread**, mark an individual entry read/unread, or mark the visible page read. Only the captured page's maximum 30 keys are changed; newer arrivals remain unread. Opening or refreshing never marks items read automatically. Older pages cover retained history. Existing review decisions also create a conversation message; these are distinct retained source entries. Missing sources disappear; read-state rows are retained without recreating deleted content.

An active visible browser checks at most once per minute. Background checks do not extend the 30-minute idle login. An established bell displays **?** after a failed check instead of inventing zero; reopening the center explains unavailability, and later checks recover. Polling needs JavaScript; sidebar/portal links and explicit forms work without it. The bell is project activity, not unread email. No message bodies, payment references, unpublished ZIPs or administrator email contents are returned by the count endpoint.

Activity queries and read actions do not modify business records. If activity storage is unavailable, clients can still send project messages and the center discovers them after recovery. New activity kinds, external email dispatch, preferences, project-stage timeline, monitoring/renewals/tickets and full P-07 remain pending. No automatic retention/deletion is introduced. Backups must include read state along with the underlying records and existing private delivery/payment storage. A consistent full backup is required for recovery; code-only downgrades are unsupported.
