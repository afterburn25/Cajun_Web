## Delivered scope

Current authorized staff can prepare private local email drafts for assigned sending accounts. Drafts belong to their author; site ownership does not bypass mailbox grants or reveal another author's drafts. Staff can save/reopen/edit, preview escaped plain text, insert a permitted active canonical template, and retain discarded drafts. The saved sender account/revision is explicit, changes require confirmation, and account/global permission loss removes access immediately.

Recipients are bounded separate To/Cc/Bcc lists of bare ASCII addresses, with at most20 total; duplicate recipients and header/control injection are rejected. Subject/body use bounded valid UTF-8 plain text. Unfinished empty fields remain valid for drafting. Template insertion checks current visibility, status and revision, uses the existing canonical engine, and creates an editable snapshot with explicit replacement confirmation. No automatic client-record lookup is introduced.

Current-authority reads/writes use the shared staff mutex. Optimistic draft revisions prevent overwrite; a stable form id and exact initial-payload replay rule avoid duplicate creates after lost responses. Strict metadata audit and mutations commit together. Stale edits retain submitted text; a concurrent discard renders a separate escaped unsaved copy without changing the saved discarded record. No message body or Bcc content is put into audit/history.

Two additive tables retain current private draft content and metadata history. Fresh setup prepares empty ready storage; upgraded owners explicitly prepare it using their current password. No mail credential is decrypted for drafting. SMTP, server Drafts synchronization, Sent-folder writes, reply/forward, attachments, HTML composition and OAuth are not implemented by this release. No Send button is provided.

## Owner procedure and limitations

Choose FULL-PROJECT for development, COMPLETE-UPLOAD for fresh installation, or UPDATE for recognized installed versions through1.20.0. Back up website, database, private storage and all original encryption keys together. UPDATE stages cwp-update-1.21.0 and uses the existing authenticated owner workflow. File recovery preserves additive records and is not a database downgrade. Follow START-HERE and MIGRATION-INSTRUCTIONS.

Open My email accounts and My email drafts. Upgraded owners first prepare local drafts. Staff need current Send permission and an explicit Send grant for the selected account. Select the sender, enter text/recipients, optionally insert an active template, preview and save. Discard keeps the last saved text in the author's discarded list. Unsaved conflict text can be copied into a new draft while current access remains valid.

This release has no real mailbox/provider/merchant or target-host acceptance. Real mail sending, full synchronization, broader20i inventory/hosting/domain/VPS operations, SSH and billing integration remain separate roadmap work.
