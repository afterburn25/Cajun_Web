# Client website ZIP delivery

Claim, 2026-10-13: Codex implements bounded P-06 on `codex/client-deliveries`, from main `cb7556a2837a0b374392541180e2ed2d670a1edd` / published v1.8.0. Own additive delivery schema/archive inspection, admin/client adapters, installer, tests and continuity documents. Devin retains public portfolio PR #7. Payment processing still needs actual merchant acceptance; this independent portal work can progress without credentials or live operations.

Staff with client-workspace access upload an explicitly prepared ZIP, label its version/scope/source revision and supply handover notes. Upload validates bounded contents without extracting or executing code, produces an immutable manifest and checksum, and stores guarded files outside the web root. Drafts are private to authorized staff. Publication requires a fresh manifest review, current owner password and explicit content/license/client-scope confirmation. It never packages the agency installation or downloads arbitrary remote sources.

Every client list/detail/download is scoped to the current owned project and active identity. Portal-wide and project lists retain latest and earlier published versions. Download uses authenticated streaming with integrity verification, strict audit and single-byte-range resume; it never exposes a permanent public storage URL. Support must have its separate download grant, is revalidated and attributed. Publication does not require paid-in-full or silently withhold delivery.

Boundaries: up to 50 MiB compressed, 200 MiB expanded, 1000 entries and 32 MiB per file; 250 MiB per project / 1 GiB per installation. Reject path traversal, ambiguous/colliding paths, links/special files, encryption, nested archives, common secret/config/log/database paths, obvious embedded credentials and corrupted contents. Require HANDOVER.md and LICENSES.md. Checks do not prove absence of all secrets or transfer rights; explicit owner review is still necessary. Scope labels are standalone static site or files-only (database/content excluded). SQL/database exports, generated builds, dynamic restore orchestration, larger background jobs, automatic retention/deletion and notifications remain pending. No live deployment, provider call or customer email.

Additive owner setup preserves existing records/private files and refuses incompatible or unrecognized populated tables. Published bytes/metadata are immutable; prior downloads remain available while client access is authorized. Upload/publish retries, concurrent versions, audit/filesystem failure, unsafe ZIPs, client isolation, expired/revoked/support access, download hashes/ranges, mobile UI, fresh install and retained-1.8 update acceptance must pass before publishing v1.9.0. Implementation and release gates are pending.

Archive API references reviewed 2026-10-13: [PHP statIndex](https://www.php.net/manual/en/ziparchive.statindex.php), [entry attributes](https://www.php.net/manual/en/ziparchive.getexternalattributesindex.php), [indexed streams](https://www.php.net/manual/en/ziparchive.getstreamindex.php). PHP ZIP is required only for this delivery feature; other existing modules must remain usable if it is unavailable.
