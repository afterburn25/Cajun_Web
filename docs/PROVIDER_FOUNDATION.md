# Hosting provider foundation

Started 2026-10-13 as an independent Devin increment under the dependency-gate policy ([DEPENDENCY_GATES.md](DEPENDENCY_GATES.md)): HC-07's external gate (`Awaiting API verification`) does not block the implementable portion — the modular adapter contract, credential boundary, connection-test contract and idempotency/reconciliation model. Branch: `devin/provider-foundation`. Scope: the provider contract core only — no admin UI, no persistence, no real 20i calls.

## Implemented component

The standalone PHP 8.2+ classes in [foundation/provider](../foundation/provider) need no framework, database, network access or Composer installation. Keep this directory outside deployment packages until the adapter contract is agreed and the release inventory is updated.

- [ProviderAdapter](../foundation/provider/ProviderAdapter.php) — the provider contract: `id()`/`label()`, a declared `capabilities()` matrix, `supports()`, a non-mutating `probe()` for connection checks, and `execute()` for operations.
- [ProviderCapability](../foundation/provider/ProviderCapability.php) — one operation's support state: `supported`, `unsupported`, or `unverified`. HC-07 requires that unverified endpoints are never treated as supported.
- [ProviderCredential](../foundation/provider/ProviderCredential.php) — account identity plus a lazily-resolved secret. The resolver belongs to the caller (the site adapter decrypts with the installation private key, matching the SMTP credential convention); the object never stores, logs or serializes the secret. `masked()` exposes at most the last four characters and never the whole value — secrets of eight characters or fewer mask completely.
- [ProviderOperation](../foundation/provider/ProviderOperation.php) — a dotted-lowercase operation name, caller-supplied params, and a caller-generated idempotency key.
- [OperationResult](../foundation/provider/OperationResult.php) — durable outcome: `succeeded` / `failed` / `retryable` / `unsupported` / `uncertain` / `in_progress` / `conflict`, provider code, external ID, attempt count, replay flag. Messages are bounded printable classifications (≤200 bytes, no control characters). Adapters must supply safe classifications; length/character checks alone cannot identify or redact arbitrary provider text or credentials.
- [ConnectionCheck](../foundation/provider/ConnectionCheck.php) — classified probe outcome: `verified` / `authentication_failed` / `unreachable` / `unsupported` / `unknown`. VERIFIED means credentials authenticated; it does not certify any operation. UNKNOWN is the honest verdict for post-send ambiguity (timeout, protocol break, lost result, unaccepted response shape) — never reported as a pass or a clean failure. Details are bounded printable classifications (≤200 bytes, no control characters).
- [HttpTransport](../foundation/provider/HttpTransport.php), [TransportRequest](../foundation/provider/TransportRequest.php), [TransportResponse](../foundation/provider/TransportResponse.php), [TransportException](../foundation/provider/TransportException.php) — the outbound HTTP boundary. Requests enforce https-only URLs with no embedded credentials and finite bounded timeouts; HTTP error statuses are returned while connection-level failures throw. `TransportException` carries only a finite failure kind (`connect`/`timeout`/`tls`/`protocol`/`unavailable`/`unknown`) — raw transport text is unrepresentable.
- [OperationLedger](../foundation/provider/OperationLedger.php) + [LedgerClaim](../foundation/provider/LedgerClaim.php) — durable atomic reservation store. `claim()` binds an idempotency key to a canonical request fingerprint **before** any remote call and returns `claimed` / `replay` / `in_progress` / `uncertain` / `conflict`; `record()` writes the terminal result under the claim (first result wins). The site adapter implements this over the database with a unique key column and a single atomic claim statement.
- [ProviderGateway](../foundation/provider/ProviderGateway.php) — the enforcement point callers use: refuses unsupported/unverified operations before any transport call, claims the key before executing, retries only idempotent operations within a bounded [RetryPolicy](../foundation/provider/RetryPolicy.php), and records honest terminal verdicts including `uncertain`.
- [ExternalResource](../foundation/provider/ExternalResource.php) — local↔provider reconciliation record. `link()` records a *claim*; `verify()` confirms only when the provider-reported ID matches, recording a `mismatch` otherwise. Ownership is never inferred from email or domain matches.

## What this component deliberately does not do

- No 20i endpoint URLs, request schemas, or response shapes — those are adapter-time decisions that require inspecting the logged-in My20i API documentation and a test account (external gate: `Awaiting API verification`).
- No credential persistence or encryption — the secret resolver is injected; storage with the installation private key is the site adapter's job.
- No admin settings screens, no schema, no queue — foundation contract only.
- No real provider calls are possible from this component alone; it has no bundled transport implementation.

## Contract semantics

- `ProviderGateway::perform()` is the only execution path. It checks `supports()` first — unverified and unsupported operations return an `UNSUPPORTED` result with zero transport calls and are not recorded.
- **Atomic reservation.** Before any remote call, the gateway durably claims the idempotency key through `OperationLedger::claim()`. The reservation — not a post-hoc record — is what prevents duplicate execution: a second caller for the same key observes `in_progress` while the first runs, `replay` after a terminal record, or `uncertain` once the reservation outlives `OperationLedger::RESERVATION_TTL` (120s) without a record (a crashed executor). Durable implementations must claim in one atomic statement (unique key + `INSERT`); a `SELECT`-then-`INSERT` pair reintroduces the race.
- **Request binding.** The claim binds the key to a canonical fingerprint: SHA-256 over provider id, account identity, operation name and a type-preserving canonicalization of params: map keys sort recursively, list order is semantically significant and never sorted, and a map never collapses into a list (numeric-key maps keep object type even when keys become sequential). Objects, resources, non-finite numbers and graphs beyond bounded depth/size are rejected before any claim. Reusing a key for a different request returns `conflict`; the same request with map keys in a different order replays.
- **Retry is operation-aware.** Only capabilities declared `idempotent` (read-only, or provider-documented idempotent writes) retry within `RetryPolicy`. Non-idempotent operations get exactly one attempt: an ambiguous outcome — `TransportException` (which may fire after the request was sent) or a 429/5xx response — is recorded `uncertain`, never retried, never re-executed. `uncertain` verdicts are durable terminal states requiring provider-side reconciliation before any retry.
- **Honest uncertainty.** Exactly-once remote execution is impossible in principle: a crash between the provider applying a write and the durable record leaves truth unknown. That state is reported `uncertain`; nothing in this component silently re-executes a possibly-landed write. If `record()` itself fails after execution, the caller receives `uncertain` rather than a false verdict.
- **Redaction.** `TransportException` stores only a finite `kind`; raw error text, URLs, credential fragments and response bodies are unrepresentable and never reach results or ledger rows. `OperationResult` enforces short printable messages. `checkConnection()` maps pre-send transport failure to `unreachable` + kind, and post-send ambiguity (`timeout`/`protocol`/`unknown`) to `unknown`.
- **Finite numerics.** Timeouts and backoff reject non-finite floats (`NAN`, `±INF`) as well as out-of-range values.
- `probe()` must never mutate provider state.

The dependency-free [test runner](../tests/provider/run.php) uses a conspicuously-marked fixture adapter (`FixtureTwentyIAdapter`, fixture key `fx-key`, `fixture.invalid` endpoints) and scripted transport — **no real 20i responses are used or claimed**. 171 named checks cover credential masking (including short secrets), finite-value validation, the support matrix, atomic claim/interleave semantics, type-preserving canonical request binding (map-vs-list shape, reordered-map equivalence, list-order significance, bounded/restricted param graphs, malformed UTF-8 map-key rejection before claim, valid nested Unicode key replay), idempotent retry, uncertain-write reconciliation (including a crash-after-write fixture), failure redaction, probe classification (strict-shape VERIFIED only (JSON object/list identity preserved — objects, scalars, null, malformed/trailing or over-depth bodies reject as `unknown`), post-send ambiguity as `unknown`, bounded check details) and resource reconciliation. A `FileLedger` fixture + `file_ledger_worker.php` race **four real OS processes** under `flock` to prove the claim contract outside scripted single-thread interleaving — one claims, three observe `in_progress`. [GitHub provider workflow](../.github/workflows/provider.yml) runs syntax + the suite in official PHP 8.2 and 8.4 CLI containers with no network and no secrets.
