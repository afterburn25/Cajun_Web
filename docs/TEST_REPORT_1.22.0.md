## Delivered scope

Authorized staff can explicitly send a saved plain-text draft from a currently assigned sending account, review its exact saved recipient/content snapshot, and inspect private submission history. A separate unchecked confirmation and Send action are required. Current global Send permission, account Send grant, author ownership, CSRF, exact draft revision and account revision are checked again at dispatch. Owners do not gain access to other authors' drafts or Bcc content. Upgraded owners prepare additive local submission storage with their current password; fresh setup includes empty ready storage.

The maintained PHPMailer7.1.1 MIME builder preserves deterministic Message-ID, Date, body and private Bcc envelope recipients without a Bcc header. The bounded SMTP transport requires verified TLS with hostname/SNI and approved address pinning, attempts all recipient commands before DATA, and applies a total deadline. It never automatically retries a transmission. A durable attempt record is committed before dispatch; accepted, uncertain or unresolved attempts block resend even after draft edits. Audit/result persistence failure after transmission remains unresolved.

Results distinguish accepted by the sending server, explicit rejection, not submitted, and unknown outcome. Server acceptance is not recipient delivery. Lost or malformed confirmation after the final terminator remains unknown. No server Sent/Drafts synchronization, attachments, HTML composer, reply/forward or OAuth is added.

## Installation and limits

Use COMPLETE-UPLOAD for a fresh installation, UPDATE for recognized installed versions through1.21.0, or FULL-PROJECT for development. Back up website, database, private storage and every original encryption key together. Follow START-HERE and MIGRATION-INSTRUCTIONS; UPDATE stages cwp-update-1.22.0 in the existing authenticated owner workflow.

Open My email accounts and My email drafts. Save and review the draft before Send. Owners upgrading from an earlier release prepare submission storage first. Sending requires a configured compatible account and current grants. An accepted result means the SMTP server accepted responsibility; verify uncertain outcomes before any separate action. The software does not promise delivery or a safe automatic retry.

No real mailbox/provider/merchant or target-host acceptance is claimed. No live deployment, customer message, charge, provider write or SSH operation occurred in testing. Broader20i/hosting/domain/VPS operations, SSH, billing integration and remaining roadmap features stay separate. Prior published releases remain unchanged.
