## Delivered behavior

Client account edits carry the saved account version. If another administrator has changed that client, the older form is refused and a safely escaped copy of the unsaved details is retained beside the current accounts. Staff with the delegated client-management permission retain access. Account changes and invitation operations are serialized and audited atomically. Current authority is checked again after competing work.

Client edits and invitation changes invalidate older client sessions. An invitation is accepted only for the active client with an unused, unexpired token; simultaneous activation cannot set two passwords. Replacing an invitation invalidates its earlier link. The private invitation link is displayed for manual sharing; this action does not send email. Client administration is refused while using a client-support session.

The release also retains reviewed internal hosting lifecycle, journal, owner records, durable dispatch fences and explicit local provisioning-retry groundwork. It does not activate a hosting control panel, background worker, fresh hosting storage or a provider write. Later deletion retry, canonical reconciliation, durable reconciliation, service agreements and Devin's new inventory reader are separate unmerged work. Existing website design, client workspace, one-page keyless installer and mail Send behavior remain.

## Installation and boundaries

Use COMPLETE-UPLOAD for a fresh installation, UPDATE for recognized installed versions through 1.22.0, or FULL-PROJECT for development. Back up website, database, private storage and all original encryption keys together. Follow START-HERE and MIGRATION-INSTRUCTIONS. UPDATE stages `cwp-update-1.23.0` for the existing authenticated owner update flow.

The client safeguards apply to the existing Clients administration. Review retained conflict details before deliberately entering a new edit. Leave a support session before administering client accounts. Existing local mail sending still requires configured accounts and current grants, and SMTP server acceptance does not prove recipient delivery.

All test records, accounts and endpoints are synthetic. No real mailbox, merchant, provider or target-host acceptance, customer message, charge, SSH session, production provider operation or deployment is claimed. The complete 20i implementation belongs to Devin under [issue #2](https://github.com/afterburn25/Cajun_Web/issues/2); remaining roadmap work continues separately. Previous published versions are preserved.
