## Delivered scope

Owners can save one 20i General API key in a protected profile, enable or disable explicit checks, replace or clear the key, and inspect settings and connection history. Current owner identity, password confirmation, CSRF, saved revisions and the shared staff lock protect changes. Credentials are AES-GCM encrypted with a separate private provider-master.key bound to the installation/profile/environment. Keys are never refilled or projected in history; a missing original key is not silently replaced over saved ciphertext.

Saving and viewing make no request. Explicit connection checks use only GET https://api.20i.com/package, public DNS validation, pinned verified TLS, fixed request options, bounded transfer/header/body limits, and no proxy, redirect or retry. Host DNS has its own resolver timeout. The key is base64-encoded once for this provider. Only an accepted JSON list within the cap establishes this read; object/malformed/error/ambiguous results do not establish success or broader permissions.

Intent commits with strict audit before DNS, with current authority rechecked before decryption and after network. Network work holds no InnoDB transaction. Finite terminal results commit separately with audit; process loss remains incomplete. History identifies saved revisions and historical settings. Shared cooldown and per-owner limits restrict repeated checks. No package contents or raw provider errors are stored.

Four additive tables retain the profile, revisions, check intents and terminal results. Fresh installation prepares empty ready storage; upgrading owners explicitly prepare it using their current password. Other provider operations remain unavailable, including after a successful check.
