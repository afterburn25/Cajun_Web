## Delivered scope

Assigned staff can explicitly load the newest 20 INBOX headers from each saved enabled email account. Current global mail.read permission, mailbox assignment and saved revision are mandatory, including for owners. Public DNS destinations are validated, the numeric connection is pinned and original-hostname TLS is verified. Maintained ImapEngine 1.25.6 and MIME parser 4.0.6, 36 locked packages and licenses are bundled byte-for-byte for shared hosting; customers do not run Composer.

Read-only EXAMINE and BODY.PEEK preserve read flags. Exact account/folder/UIDVALIDITY/UID identities are retained. Subjects, senders and provider dates are untrusted escaped text; remote images never load. Headers exist only in the current response, with private/no-store and no-referrer headers. No body, attachment, outgoing mail or automatic polling is included. An incomplete, failed or oversized batch never appears as a successful empty mailbox.

Two additive tables retain started requests and separate immutable terminal outcomes/counts, each committed with strict audit. DNS occurs outside the staff lock; credentials and grant/account edits serialize afterward, without a database transaction spanning network work. Authority repeats before credentials and display. A failed terminal audit returns no headers and leaves an incomplete intent. Cooldown is 15 seconds per account, with 120 starts per staff hour. Personal request history requires the current mailbox assignment. No header text or credential is retained in that history.

## Installation, updates and limits

FULL-PROJECT is sanitized development source. COMPLETE-UPLOAD extracts production contents directly for fresh setup. UPDATE stages cwp-update-1.17.0 for installed 1.0.8 or 1.1.0 through 1.16.0 sites. Back up website, database and private storage including mail-master.key together. Follow START-HERE and MIGRATION-INSTRUCTIONS; do not fresh-install over existing data or manually copy staged payloads. File recovery preserves additive database records and is not a database downgrade.

Fresh setup creates empty inbox request storage. After upgrading, an owner opens Email accounts and uses Prepare inbox reading with their current password. Assign each reader global mail.read and account Read access, including owners; then use My email accounts → Open inbox → Load recent headers. GET navigation does not contact a mailbox. Save account changes before requesting headers; a stale form is refused. Known interrupted requests remain incomplete, and older saved revisions are historical.

Incoming modes are 993/TLS and 143/mandatory STARTTLS with AUTH=PLAIN. Target-host DNS, egress, OpenSSL/system trust store and real account compatibility still require acceptance. DNS uses the operating-system timeout; after DNS the receiving operation has a 20-second deadline, 5-second connect/I/O limits, 393,216 received bytes, 256 lines, 4,096 parser tokens, nesting 12 and 16 KiB per header literal. No custom CA/private-network/proxy switch is offered. OAuth, message bodies, attachments, compose/send, combined folders and exact-message email bells remain future work. Website system-email settings are unchanged. No real mailbox, hosting deployment or payment/provider/SSH operation occurred.
