# Portfolio browsing — 1.11.0

Candidate implementation is present; integrated acceptance and publication remain pending.

Open Portfolio and choose a category. Each filter is a real link with a shareable address; navigation works with JavaScript disabled. With JavaScript, cards update immediately, the selected category is announced, a result count changes, and browser back/forward restores the previous selection. Modified clicks retain ordinary browser behavior. All work clears the filter; a category actually named `all` still selects only its own projects.

Categories are exact and case-sensitive after trimming surrounding whitespace. Unknown categories show a clear empty state and a link back to all work. Numeric category strings and Unicode names retain their values. Existing project sort order is honored, with slug and identifier as deterministic tie breakers. Only published projects are included, even in hidden card markup or category lists. Published detail URLs use exact slugs; unavailable, draft, archived and differently cased slugs return the existing 404 page. Duplicate published slugs are rejected by the component; the real projects schema already requires unique slugs.

Administrators keep using existing project and capture controls. Concept labels remain visible. Existing case-study descriptions, challenges, solutions, deliverables, live links, device captures and walkthroughs are retained. Before/after controls require two different available media references; this validation does not establish that the images are authentic client work. Administrators remain responsible for approved content and factual labels. No example clients, claims, prices, ratings or results have been added.

The adapter maps current `projects` rows (`id`, `slug`, `category`, `sort_order`, `is_demo`, publication state and media) to the standalone portfolio contract. Malformed rows are logged and skipped. No new schema or admin subsystem is introduced. Canonical component copies are bundled under `app/foundation/portfolio`; the builder rejects divergent copies and refreshes installer inventory hashes.
