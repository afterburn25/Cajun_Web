## Reoffers and captured forms

An agreement can belong to only one renewal binding for its entire history. A request can have up to128 successive immutable bindings; it is not permanently unique to one agreement. Only the newest binding can be actionable. Before offering another agreement, the previous agreement must be terminal using existing actions: `abandon` while pending consent (including accepted terms awaiting activation), or `cancel` after activation/pause. Client quote decline and owner quote withdrawal use these existing agreement actions and leave the renewal request intact. Declining or withdrawing the request itself remains terminal under its existing contract.

An expired unconsented offer cannot receive new consent. Explicitly withdraw it, then link a new agreement to the same still-pending request. An acceptance recorded before expiry is retained; expiry does not silently cancel accepted terms. Prior offers, consent and end events remain visible. A revised request requires new reviewed terms after the old agreement is ended.

Binding and generic agreement mutations share the existing staff mutex and transaction. If generic client consent happens first, binding refuses an already-consented agreement. If binding happens first, the old generic form lacks the exact binding fingerprint and cannot record consent. Captured old agreement URLs cannot accept a replaced, expired, revised or reassigned offer. Withdrawal/cancellation and historical reads remain available under current actor authority when current registrar context is stale.

## Authority and recovery

Binding and acceptance retain exact current registered-domain ID/name, explicit client assignment/revision, original assignment event/audit, account/revision, key fingerprint and sealed-credential digest. Fresh latest registrar evidence is required for new acceptance. Exact common-start audit correspondence and latest audit insertion order must agree with the chosen intent sequence, so a later failed/unfinished intent cannot be moved below an old successful observation to revive authority. Renewal-date and upstream-expiry tables are not preparation prerequisites. Client rendering does not unseal credentials or send a provider request.

The new binding table stores canonical originals only. Per-request independent heads/counts and a retained global count are updated with the binding and exact actor/hash audit in one transaction. Full binding chains, original request prefixes, original agreement terms and existing agreement event/audit sequences are validated before use. Earlier agreements must have ended before the next binding's audit; event times remain monotonic when the clock rolls back. Missing families, heads, counts, audits or original records fail closed. Preparation never silently replaces established history. Simultaneous destruction of every independent witness is not recoverable from local evidence alone.

The generic agreement guard must remain active even when a family or marker is lost; missing established history cannot become an unbound agreement. Bound agreements are excluded from the generic shared-hosting offer in both UI and backend. `ServiceOrderDocument`, original invoice hashes, recurring invoice-origin safeguards and all existing agreement event argument formats remain unchanged.
