## User outcome

Assigned staff can select a recent inbox header and explicitly load that exact message. The page shows escaped sender/subject/date claims, a plain-text body and, when available, a sanitized formatted view. It explains excluded remote images and attachments. Opening preserves mailbox flags. Sending, downloads, arbitrary folders and automatic sync remain separate increments.

## Identity and transport

Bind the request to account ID, saved revision, literal INBOX, validated unsigned-32-bit UIDVALIDITY and UID. Revalidate current global/read assignment and session before accepting intent, after DNS, before credentials, before UID FETCH, after transport and before display. A changed revision, epoch, deleted/missing UID or mismatched response must return unavailable. Do not fall back to sequence numbers or another message.

Use the fixed message operation over the maintained parser. Preserve the current header reader's 16 KiB literal profile. Message profile: one message, raw MIME <=256 KiB, fixed total receive budget with explicit protocol overhead, read-only EXAMINE and UID FETCH BODY.PEEK[], unchanged public DNS pinning/original-host verified TLS, 5-second I/O and 20-second total after DNS. Query exact UID/FLAGS/RFC822.SIZE before requesting MIME; require matching identity and size in the body response, exact literal length, complete tagged success, no unexpected message/body or unsolicited mutation responses. Reject oversize before fetching the body. No arbitrary command or larger caller-supplied limit.

Retain strict started/terminal access audit without body/header text. Reuse the staff serialization and no-DB-transaction-over-network pattern. Message reads need their own current-purpose request/result records, rate limits and finite outcomes, rather than pretending header-list results are body accesses. They must survive update/recovery with their original key and account history. The application serializes and counts committed attempts: one per account per two seconds, plus 240 per account and per staff hour. Denied cooldown/hourly requests do not connect or create a new attempt; failed/interrupted started requests remain counted. Header refresh limits stay separate and unchanged.

## MIME and display boundaries

Reuse the pinned maintained MIME parser with instance-local NullLogger and global definitions/plugins disabled. Limits: 32 parts, nesting 8, 128 headers per part / 512 aggregate, 16 KiB part header / 64 KiB aggregate header, bounded token/comment work. Force full bounded part enumeration before selection; read only selected inline text/plain and text/html streams in bounded chunks, never unrestricted getContents. Refuse decoded text >128 KiB or HTML >64 KiB. Do not decode or expose attachment bytes. Reject parser budget errors before returning content. Plain text is escaped and control/bidi handling must be explicit without destroying line breaks or normal Unicode.

Local study confirms plain, multipart alternative, base64 and ISO-8859-1 quoted-printable decoding with those limits; part/depth/header/raw/decoded excesses are refused. The maintained parser tolerates a missing final multipart boundary with no default ERROR. This must be documented/tested explicitly: a complete fetched malformed message is distinct from a truncated network response, whose exact literal/size/tag checks must always reject. Do not claim the dependency rejects every malformed MIME message. Consider validation-level diagnostics and honest unavailable/format-recovery outcomes without leaking remote exception text.

Formatted renderer: Symfony HTML Sanitizer 7.4.20 with minimal formatting allowlist, no styles/classes/IDs, no media/forms/frames/scripts/SVG/MathML/unknown subtrees, and only explicit http/https links with forced noopener/noreferrer. This adds ext-dom and four packages relative to the existing bundle; verify host requirement behavior and bundle every exact byte/license. The built-in max-input setting truncates silently, so refuse input before invoking it. Iteratively bound the parsed tree before recursive visiting (<=2,048 nodes, depth <=32); test both maintained parser paths on actual PHP 8.2 and 8.4. No upstream source edits.

Use a sandboxed isolated iframe with restrictive CSP, no-referrer and private/no-store. The iframe permits only popups and escaping the popup sandbox; validated http/https links carry forced blank target and noopener/noreferrer. It grants no scripts, forms, same-origin or top navigation. Its CSP allows no resources/scripts/forms/connect/frame content and only the trusted nonce style. Provider HTML never contributes CSS. UI must never inject provider HTML into the application DOM. Test reparsing/mutation, encoded dangerous URLs, namespace transitions, remote trackers, CSS/resources, event handlers, malformed UTF-8, excessive nodes/depth, DOM clobbering and attempts to escape the iframe. Content remains in the authorized response, not shared DB/session caches.
