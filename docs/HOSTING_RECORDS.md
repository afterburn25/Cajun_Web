# Local hosting record storage

Unreleased HC-08 adapter on `codex/hosting-storage`, starting from journal8bbd209 (PR80, itself stacked on79). This prepares guarded application code and canonical deployment mirrors; there is no router, admin action, fresh-install activation, provider operation or new release version. Existing published1.21 and separate mail1.22 candidate remain unchanged.

An authenticated current owner with a prepared client workspace can explicitly prepare additive native MariaDB tables, approve a local package snapshot for an active client and save supported local lifecycle commands. Setup and mutations recheck the current password. Staff administrators and client-support context are denied even if they have every existing permission. Reads recheck current owner identity and require the explicit account/client pair; inactive-client records remain readable to the owner. No client-facing access is introduced.

`hosting_records` retains creation identity, client, approving owner, creation time, original canonical journal, current journal, fingerprint and revision. `hosting_record_events` retains globally unique event ids, account/revision uniqueness, attributed input, time and before/after fingerprints. InnoDB transactions under the existing staff mutex commit a journal change, immutable event and strict audit together. Current authority is checked after acquiring the mutex. Stale revisions, changed request reuse, wrong client selections and inherited transactions are refused. Exact create/event replay returns saved state without inserting another event or audit entry.

Every load reconstructs the canonical journal, compares its immutable original terms and identity, then verifies each retained event and hash chain. Missing, inconsistent or unsupported data is preserved and refused. Fingerprints detect differences; they are not signatures or proof of a real provider operation. No HTTP JSON import or generic remote-result command is exposed. The generated deployment mirror remains byte-for-byte canonical.

The local command allowlist is domain association, grace deadline, opening/closing a dispute, cancellation of a never-provisioned local order and requesting cancellation. The existing lifecycle still decides which states permit those commands. A local domain association does not register a domain or change DNS; a cancellation request does not arm deletion. Provision/retry/suspend/resume/deprovision, observations and reconciliation are explicitly rejected by this adapter. Their future adapter must commit an exact operation/profile/attempt-bound dispatch fence before any credential or network use, then preserve unresolved outcomes after interruption. This work does not claim that fence exists.

The setup routine validates exact columns, binary encodings, defaults, indexes and restrictive relationships. It refuses unknown versions and populated unrecognized storage. DDL is additive; a failed audit can leave empty verified tables while readiness remains unset. There is no drop/reset/rebuild behavior. Raw journal content and passwords are excluded from audit details. Local package approval does not establish a paid order, valid provider package mapping or verified remote entitlement.

Native PHP8.2/8.4 MariaDB tests are prepared for setup incompatibilities, current owner/password/client checks, process restarts, concurrent stale and identical requests, authority loss while waiting, strict audit rollback, changed/missing history and durable synthetic unknown outcomes. Active and uncertain remote states are inserted only by an isolated test fixture, never a production import or actual provider request. Local syntax and generated dependency checks precede CI; no native acceptance is claimed until downloaded named reports are verified.
