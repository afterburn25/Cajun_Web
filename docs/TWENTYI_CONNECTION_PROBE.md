# Isolated 20i connection probe

This is preparation for the [owner settings contract](PROVIDER_SETTINGS_CONTRACT.md), outside the deployed application. It reuses the reviewed [provider foundation](PROVIDER_FOUNDATION.md). A concrete fixed HTTP transport now has local isolated HTTPS evidence. Encrypted settings, database history and admin forms remain unimplemented; no real 20i request has been made by this component.

[TwentyIAdapter](../foundation/twentyi/TwentyIAdapter.php) constructs exactly one GET to `https://api.20i.com/package`. Its credential resolver supplies a raw General API key; the adapter base64-encodes it once into the bearer header. Provider identity and local credential bounds are checked first. Only HTTP 200 with a JSON list within 1 MiB and depth 32 verifies this narrow connection. Objects, including empty or numeric-key objects, do not become lists. Item fields are not projected, persisted or represented as a verified inventory schema.

401/403 produce a fixed authentication rejection. Rate limits, server errors, other statuses, malformed responses and size limits produce fixed UNKNOWN classifications. The gateway maps finite transport exceptions to unreachable or unknown depending on their declared phase. There is no automatic retry, redirect or general endpoint input in this adapter. The current transport has local synthetic acceptance below; its PHP matrix and independent review remain required before application integration.

Fifteen advertised operations remain unverified; `supports()` always refuses them, and direct `execute()` also refuses before credential resolution or transport. [ProbeOnlyLedger](../foundation/twentyi/ProbeOnlyLedger.php) exists only to satisfy the gateway constructor for the connection path: every claim/record throws. It is not durable storage and must never be represented as production idempotency or used to enable mutations.

The [named synthetic suite](../tests/twentyi/run.php) covers fixed request and one credential encoding, response shape/depth/size, non-success statuses, finite transport ambiguity, no retries, invalid credentials, and refusal of gateway/direct operations. Default PHP and no-extension execution each pass 120 checks locally. The [PHP matrix](../.github/workflows/twentyi-probe.yml) runs without network access and retains named results. These tests do not establish account entitlements, real HTTP behavior, native database concurrency, application authorization or deployment.

## Fixed HTTP transport and evidence

[FixedHttpTransport](../foundation/twentyi/FixedHttpTransport.php) resolves only `api.20i.com` through the existing canonical resolver. It rejects an entire answer set containing any private/reserved destination, including mixed public/private results, then pins one validated address. Resolve before credential access. Blocking DNS remains subject to the host resolver's timeout; the transfer's five-second connect, 15-second total and five-second low-speed limits start after resolution. Do not represent that as a hard wall-clock bound on operating-system DNS.

The transport independently validates the exact method, URL, null body and permitted headers. PHP/cURL supplies HTTP framing and TLS, using the original hostname, certificate/hostname verification, TLS 1.2 minimum, a pinned address, fresh connections, ignored netrc, disabled proxies and no redirects. Counting callbacks cap all headers at 16 KiB and body bytes at 1 MiB. Responses expose no remote headers. Literal raw/base64 request-key echoes are refused; this is not a general redaction filter. All returned body data remains internal to the adapter and must never enter logs or UI/history. Cap/protocol faults classify UNKNOWN through the finite `protocol` kind; the adapter's independent post-hoc body cap uses `response_limit`.

Current authority callbacks run before cURL initialization, immediately before execution and before returning any response body. The application must additionally resolve credentials under current authority and serialize staff/profile changes with the existing staff mutex. The transport has no application identity or permission model of its own.

Local PHP 8.4.25 verification: **333 named actual loopback HTTP/TLS checks**, **32 default request/DNS policy checks**, and **33 policy checks when cURL initialization is unavailable**. Cases cover real certificate/hostname/expiry rejection before HTTP authorization, chunked/partial/malformed replies, inclusive body limit, aggregate header/interim limits, timeout/trickle/stall, listening proxy canaries with zero connections, literal credential echo rejection, fixed SNI/Host, one encoded credential header, no retry/redirect and authority refusal. [TLS suite](../tests/twentyi/tls_test.py), [policy suite](../tests/twentyi/transport_policy.php).

Only the test namespace shim changes the connection port/address and trust anchor, after asserting every production option; no production test-CA/private-address switch exists. The expanded matrix builds its fixture runtime, then executes inside `docker --network none` with the repository mounted read-only and separate temporary/output mounts. Both PHP configuration modes run real cURL HTTPS where compiled into the image. `php -n` means no configuration, not removal of compiled extensions. A separately disabled `curl_init` invocation proves finite unavailable refusal. Matrix evidence for this new transport must be downloaded and inspected; the prior run 38506770388 proves only the earlier 120-check adapter.

Reviewed primary transport references: [libcurl address pinning](https://curl.se/libcurl/c/CURLOPT_RESOLVE.html), [low-speed deadline](https://curl.se/libcurl/c/CURLOPT_LOW_SPEED_TIME.html), [finite libcurl error codes](https://curl.se/libcurl/c/libcurl-errors.html), and [official PHP container build](https://github.com/docker-library/php/blob/master/8.2/bookworm/cli/Dockerfile). PHP does not expose every current libcurl error name; certificate code 60 uses PHP's `CURLE_SSL_CACERT`, and issuer code 83 is handled explicitly. The fixture images already compile cURL, so the workflow verifies availability instead of compiling a duplicate extension.
