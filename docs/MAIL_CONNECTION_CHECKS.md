# Bounded A-06 connection checks — candidate 1.16.0

Starting point: verified [1.15.0](TEST_REPORT_1.15.0.md), publication-record main ad2f39d, branch codex/mail-connection-checks. Existing multiple-account preparation, encrypted private key and explicit read/send assignments remain authoritative. Codex owns application transport, owner controls, tests and release. Application adaptation is implemented in candidate source, mirrored from canonical foundation/mail-transport. Local PHP 8.4 passes 103 policy, 13 resolver and 185 actual loopback TLS checks. The initial prototype passed PHP 8.2/8.4 CI; candidate database/HTTP/upgrade/release acceptance remains pending. This is not a release or a real-provider test.

## Next usable increment

An owner explicitly tests the saved incoming or outgoing connection from Email accounts, with CSRF, current password, exact saved account revision and an active corresponding mailbox assignment. Each button explains that it logs into that one configured server and logs out, without reading, changing or sending messages. Saved configuration never automatically connects. Plaintext transport is never offered. A success means TLS and password authentication worked at the recorded time for that saved revision; it does not establish inbox synchronization, sending eligibility, deliverability or future availability.

Public internet hostnames only, with IMAP 993/TLS or 143/STARTTLS and SMTP 465/TLS or 587/STARTTLS initially. Other saved ports remain representable but cannot be tested until their transport policy is deliberately extended. Resolve A/AAAA records once; refuse a result containing any private, local, reserved or ambiguous destination. Connect to one validated numeric address, retaining the original hostname for certificate verification and SNI. Never reconnect by name or follow server referrals. No owner checkbox can bypass verification. A separate synthetic connector in tests is injected internally; HTTP/configuration cannot select it.

TLS 1.2 or 1.3, mandatory certificate/hostname verification, no authentication before verified encryption, no downgrade. Use a monotonic operation budget after DNS and strict response/line/command/byte caps. DNS uses the host resolver; its system timeout remains a host prerequisite and must not be represented as application-interruptible. Literal/malformed/excessive unsolicited replies, absent upgrade, unsupported authentication and timeouts fail closed. No remote response or exception details, username, credential, ciphertext or message contents reach UI/audit/logs. Only finite local result codes and times are retained.

The diagnostic is a deliberately narrow finite command exchange, not a general IMAP or MIME implementation: greeting, capabilities, mandatory STARTTLS when selected, authenticated login, logout; SMTP greeting/EHLO/STARTTLS/EHLO/AUTH/logout. No SELECT/FETCH/SEARCH/STORE/APPEND/EXPUNGE, MAIL/RCPT/DATA or arbitrary command interface. Require a supported password mechanism; OAuth-only providers remain unsupported until their own integration.

Under the existing staff advisory mutex, validate current owner/password/assignment/revision and endpoint shape, enforce a 30-second account/target cooldown and 20 attempts per owner per hour, then commit a started record and strict audit before DNS. Resolve outside the mutex and without an InnoDB transaction. Reacquire the mutex and recheck current actor, password, assignment/expiry and account revision; decrypt only then and perform the bounded handshake/auth exchange. Repeat authorization/expiry immediately before every credential payload and after authentication. Network work never holds an InnoDB transaction. The advisory mutex serializes revocation/account edits with the bounded transport wait; a competing administrator change may need to retry. Process termination leaves an honest incomplete record, never presumed success. A separate immutable terminal result and strict audit commit together; failed final audit leaves the started record incomplete. Check results are metadata and version-bound; editing an account makes previous checks historical.

## Acceptance before release

Use actual TLS sockets with a private ephemeral test CA in isolated CI: IMAPS, SMTP TLS, both STARTTLS modes, valid login, wrong credentials, hostname mismatch, untrusted/self-signed/expired certificate, missing upgrade, authentication before TLS prevention, malformed/mixed/tag-confused/oversized replies, abrupt EOF, slow peer, byte/time caps and command injection. Test DNS/IP policy separately (IPv4/IPv6, mapped/translated forms, mixed results and pinning). Capture allowed command names only, never AUTH payloads. Prove no mail submission or mailbox selection occurs.

Native database acceptance covers current owner/password/assignment/global permissions, disabled/revoked/expired identities, stale revisions, private key failure, concurrent check/edit/revoke, rate limiting, started/final strict audit failure and truthful interrupted outcomes. Actual HTTP/Chromium checks cover separate controls, CSRF, sanitized failures, preserved values, historical version labels and mobile layouts. Test real prior-release update/recovery retaining account/key/assignments, templates, reviews and consultations. Complete the standard package/Apache/exact-main/release verification.

## Library discovery and following increment

Checked upstream on 2026-10-13: PHP 8.4 moved ext-imap to PECL, so it cannot be a required shared-host capability. PHPMailer v7.1.1 has a maintained SMTP class; Webklex/php-imap 6.2.0 implements IMAP in PHP but brings several framework dependencies and its unmodified nextLine/literal reader does not provide the required aggregate response budget. Horde Imap_Client v3.1.0 has a broader dependency graph and an installer plugin. These are integration considerations, not vulnerability findings or proof of provider compatibility.

Keep this first diagnostic exchange narrow and dependency-free. Before the receiving increment, select and pin an audited maintained IMAP/MIME stack, its transitive dependencies/licenses and reproducible packaging, with bounded reads and hostile MIME fixtures. A hand-written diagnostic is not authorization to grow an unreviewed general-purpose MIME parser. Candidate MIME library zbateson/mail-mime-parser 4.0.6 supports PHP >=8.1 without requiring mailparse. Later receiving scope must bind account/folder/UIDVALIDITY/UID identity, read with PEEK, avoid remote images/HTML execution, enforce content and attachment caps and repeat current authorization at every display/download. Sending and A-08 exact-message bells follow separately; existing activity bells remain distinct.

Primary references: [PHP IMAP installation](https://www.php.net/manual/en/imap.installation.php), [PHPMailer v7.1.1](https://github.com/PHPMailer/PHPMailer/releases/tag/v7.1.1), [Webklex 6.2.0](https://github.com/Webklex/php-imap/tree/6.2.0), [Horde v3.1.0](https://github.com/horde/Imap_Client/tree/v3.1.0), [MIME parser 4.0.6](https://github.com/zbateson/mail-mime-parser/tree/4.0.6), [IMAP RFC 9051](https://www.rfc-editor.org/rfc/rfc9051.html).

Endpoint policy sources checked 2026-10-13: [IANA IPv4 special ranges](https://www.iana.org/assignments/iana-ipv4-special-registry/), [IANA IPv6 special ranges](https://www.iana.org/assignments/iana-ipv6-special-registry/), [PHP verified TLS options](https://www.php.net/manual/en/context.ssl.php). The policy deliberately rejects whole special-purpose ranges, including some globally reachable exceptions, to restrict this diagnostic to ordinary public mail destinations. No destination rule proves provider compatibility.

## Owner workflow and files

Open **Email accounts**, select a saved account and use **Prepare connection checks** once on upgraded installations. Fresh setup creates empty check storage. Preparation verifies the additive schema without changing saved accounts, assignments or the private key. Assign yourself the matching Read or Send access even if you are an owner. Save any account changes before testing, then enter your current administrator password in the separate incoming or outgoing check form. Unsaved editor values are never tested. Review the finite result under Connection-check history; no final result means interrupted/unrecorded, and Historical settings means a different saved version.

Supported password mechanisms are IMAP AUTHENTICATE PLAIN and SMTP AUTH PLAIN or LOGIN over verified TLS. An app password may be required by your provider. The server trust store and bounded operating-system DNS resolver must be configured by the hosting provider. No custom certificate/private-network bypass is offered. This feature does not read a mailbox, send a message, prove delivery or alter the website's separate system-email settings. Mailbox rendering/compose and email notification bells remain future work.

Application code is app/mail/connections.php, database/schema/mail_connections_schema.php, database/migrations/mail_connections_migrate.php and admin/views/mail_connections.php under site/. Canonical protocol/policy code remains foundation/mail-transport; the builder generates the protected shipping mirror. Tests use synthetic credentials only, with actual isolated TLS sockets plus separate injected database boundaries and clearly identified synthetic history-display fixtures. No application input selects test connectors or overrides TLS.
