## Components

- `SubmissionSnapshot` reuses canonical `DraftContent`, requires at least one recipient, exact opaque submission/draft/account identities and positive saved author/revisions, and fixes a server-supplied timestamp, selected sender and Message-ID. Its deterministic fingerprint covers the full private snapshot, including To/Cc/Bcc and content. Supplying ids/fingerprints does not grant access; current authority remains an application requirement.
- `PreparedMime::fromSnapshot()` returns immutable private MIME bytes, their SHA-256 and the original snapshot. It validates required runtime functions and the pinned maintained library version, verifies every recipient remains in the expected class, imposes a64KiB encoded-message cap and998-byte wire-line cap, and refuses unexpected Bcc/Reply-To/return/receipt headers. The **wire checksum alone does not cover Bcc**; later dispatch must bind the full snapshot fingerprint as well as the exact encoded bytes.
- `OfflineMailer` is a thin PHPMailer adapter. PHPMailer supplies MIME generation, address rendering, base64 body encoding, Q subject encoding and UTF-8-aware wrapping. The adapter folds long headers, retains the fixed UTC date rather than host-local date rendering, and encodes literal subjects so leading/trailing spaces and encoded-word-looking text are not silently reinterpreted. High-level `send()`/`postSend()` are explicitly refused. No SMTP session/credential configuration is supplied.
- `PreparationFailure` exposes only finite private error codes, with no upstream exception, recipient list or message content attached. Unsupported runtime, recipient mismatch, encoding failure and bounds failure are distinct. Original drafts/snapshots are never mutated by failed preparation.

The selected profile supplies From and envelope sender; arbitrary Reply-To, display names, read receipts and custom headers are not accepted by this preparation API. Body text is `text/plain; charset=UTF-8`, base64-encoded from canonical CRLF content with every other validated byte retained. Bcc-only mail uses the maintained library's undisclosed-recipient group; Cc-only and empty subject/body are supported. Drafts with no recipients remain valid drafts but cannot prepare a submission.

PHPMailer deduplicates recipient local parts case-insensitively. The draft grammar intentionally preserves case-sensitive local parts. Preparation therefore explicitly refuses a combination such as `Client@example.invalid` plus `client@example.invalid` with `recipient_mismatch`; it never silently removes or reclassifies a recipient. Resolving mailbox equivalence or adding broader address syntax is separate from MIME generation. No actual account/provider support is implied.

## Pinned dependency

Original PHPMailer7.1.1, commit `1bc1716a507a65e039d4ac9d9adebbbd0d346e15`, is retained under `foundation/mail-submission/vendor/phpmailer` with original LICENSE, README, composer metadata and three runtime source files. The library is LGPL-2.1; source and license notices remain intact. `vendor-source.json` records all six original file hashes and immutable upstream URLs. The adapter does not edit vendor code, and Git preserves vendor bytes without line-ending conversion.

`python tools/check_mail_submission_vendor.py` verifies the exact file allowlist, source/version, absence of symlinks and all hashes. `--reproduce` independently downloads each pinned upstream file and compares its bytes. This is a development verification step only, never an installation-time download or customer Composer requirement. The source is available from the linked immutable upstream commit and in the development checkout.
